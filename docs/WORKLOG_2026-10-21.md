# WORKLOG · 2026-10-21 · 子卡去 LP 后的 CSI 接入修复

> 版本：`CFG_VER = 0x450D`（`0xA9/0xAA` 读回 `0D/45`）
> 结果：**1080p 与 4K 画面、颜色均正常；烧录后无需重启。**
> 相关提交：`25021d2` → `b617b1e` → `5ef4a28` → `4071d54` → `b8473ac`

---

## 1. 背景

MIPI 扩展子卡做了硬件改版：**把 CSI 侧的 100Ω LP（低功耗态）分压电阻拆掉**，目的是把原 DSI
差分对改作第二路 CSI 输入。改版后原有 CSI 输入链路完全不出图，需要在不回装电阻的前提下修好。

厂家的说法是「只改 IO 约束即可，然后用 LVDS 解 MIPI」——这个方向没错，但前提是接收端是
**不依赖 LP 的接收器**。原来的 `mipi_dphy_rx_over_lvds_wrapper` 必须看到 LP-11→01→00 的
状态跳变才能锁定，FPGA 的 LP 输入现在悬空（恒定电平），所以永远等不到。

| 验证 | 做法 | 结果 |
|---|---|---|
| LP-11 恒定 | LP 输入上拉 | `FRAME_CNT` 恒 0 |
| LP-00 恒定 | LP 输入下拉 | `FRAME_CNT` 恒 0 |

⇒ 结论：LP 通路不可用，必须换 LP-free 接收器。

---

## 2. 方案

从工作区里已有的 `07_异构方案/.../uisrc/03_ip/mipi_csi_2/`（同一块板、同一颗 PH1A90、
同样的 4-lane 接法）移植 LP-free RX，落到 **`fpga/uisrc/03_ip/mipi_csi_lpfree/`（14 个文件）**。

数据通路：

```
LVDS 差分输入 ─ PH1_LOGIC_IDDRx2 + PH1_LOGIC_DYNAMIC_IDELAY
   → csi_rx_hs_data_phy      (4:1 解串, 每 lane 一个字节)
   → csi_rx_byte_align ×4    (找 0xB8 同步字, 8 个 bit 偏移都试)
   → csi_rx_word_align       (4 lane 去偏斜)
   → csi_rx_word_gear_box    (4 lane 拼 32bit)
   → csi_rx_packet_handler   (在字节流里找 CSI-2 包头, ECC 校验, 不需要 LP)
   → csi_rx_hdr_ecc / csi_rx_10bit_unpack / csi_rx_vid2stream
   → m_axis_video_tdata[39:0]  (4 像素 RAW10/时钟)
```

约束侧（`fpga/uisrc/04_pin/fpga_pin.adc`）只保留 **5 条 LVDS**：

| 信号 | 引脚 | 约束 |
|---|---|---|
| `I_clk_hs_p` | E13 | `LVDS18`, 无 INDEL |
| `I_data_hs_p[0..3]` | C14 / D14 / A15 / G17 | `LVDS18, INDEL = 20` |

8 条 LP 约束已注释保留（附回退说明），`system_top.v` 里 `I_data_lp_p/n` 端口删除。

> 该约束写法与 07 参考工程**逐字一致**，包括 data lane 的 `INDEL = 20`、clock lane 无 INDEL。

## 3. 踩到的 5 个坑

### 坑 1 · IDELAY 的 `indly_en` 是电平使能，不是脉冲

厂家仿真模型 `sim_release/ph1/ph1_logic_dynamic_idelay.v`：

```verilog
assign dly_o = #(170 + in_dly*23) i;      // ps
assign o     = indly_en ? dly_o : i;      // ← 电平！
```

原代码把 `indly_en` 接到一个"延时有效"的单周期脉冲上，等于**绝大多数时间直通、不延时**，
eye-scan 全程在测"没加延时"的信号；同时扫描范围还写成 64 档，而 IDELAY 只有 **32 档（0..31）**。

- 修法：`indly_en` 接常 1；扫描终止条件改 `scan_tap == 6'd31`。
- 版本：`0x4509`。

### 坑 2 · RX 复位引用了它自己的输出时钟 → 死锁

`S_hs_rx_clk` 是 RX 自己分频出来的。若把 `S_res_rstn_rx`（在 `S_hs_rx_clk` 域里同步出来的寄存器）
接进 RX 的复位，则 RX 被复位 → 没时钟 → 同步器不更新 → 复位永远不释放。

- 修法：`assign S_rx_rstn = S_pll_lock & ~S_dphy_rx_rst;`（只用 25MHz 域的稳定信号）。

### 坑 3 · 给例化追加端口时吃掉了收尾 `);`

`cfg_ctrl_top.v` 里 `jpeg_regfile` 例化的结束符丢失 → TD 报
`HDL-8007 syntax error near 'i2c_slave'` + black box。

- 教训：改例化端口时 old/new 串里必须包含 `);`；改完比对 `<File>`/`</File>` 与顶层连接检查。

### 坑 4 · eye-scan 的启动竞态（花屏 / 需重启）

| 场景 | 传感器状态 | 扫描结果 | 画面 |
|---|---|---|---|
| 热烧录 bit | 一直在出流 | `best_len=3`，tap=**1**（贴边） | 花屏 |
| 断电重启 | 一起重新初始化 | `best_len=32`，tap=**16**（正中） | 正常 |

同一个 bit、同一块板，结果不确定 —— 说明**测量**受启动时序影响，不是链路时好时坏。
旧的 LP 接收器没有这个问题，是因为它**根本没有 eye-scan**（固定延迟）。

- 修法（`csi_rx_phy.v`）：
  1. 扫完若 `best_len < 8` 判定不可信 → 复位扫描器与字节对齐器**重扫**，最多 4 次；
  2. 定案后用**手动模式把 tap 锁死**：可信取扫描中心值，不可信取 `FIXED_TAP = 16`；
  3. 手动步进（`0xD9`）在锁定后依然可用（每次释放沿 tap+1）。
- 效果：无论冷启动还是热烧录都落到 tap=16，**烧完不用重启**。

### 坑 5 · 红绿互换：Bayer 相位差了一行

换 RX 后画面正常但红色显示成绿色。

推理：设真实排布为 P、配置为 Q，若 R 位被当 G 读、G 位被当 R 读，红物体就会发绿。
在 4 种排布里，只有 **P=RGGB（错一行）** 或 **P=BGGR（错一列）** 会给出这个症状；
P=GRBG 会让红物体发**蓝**，不符合。

实测默认 `0xDA=0`（RGGB）即正确 ⇒ 新 RX 通路比旧通路（`ui_csi_unpacket` +
`ui_raw10_unpacket`）**早一行**，行相位翻转了。旧代码里 1080p 用 `GBRG`，其实一直在
补偿旧通路的那段行偏移。

- 结论：**1080p 与 4K 的正确 Bayer 都是 RGGB。**
- 实现：`ui_top_demosaic` 增加 `I_ypos_inv`（行相位取反），`ui_isp_top` 用
  「RGGB / GBRG 两条列相位分支二选一 + 行相位取反」覆盖全部 4 种顺序，
  由 `0xDA` 运行时选择；4K 分支固定 RGGB（即使有人在 1080p 下改乱 `0xDA`，切 4K 仍正确）。

## 4. 新增寄存器（只读调试 + 可写控制）

| 地址 | 方向 | 含义 |
|---|---|---|
| `0xD6` | R | `{unpack_valid, payload_valid, in_frame, word_align_valid, byte_align_valid[3:0]}` |
| `0xD7` | R | `{load_pulse, manual_mode, tap[5:0]}` |
| `0xD8` | R | `{0, autodone, best_len[5:0]}` — 本次扫描连续通过的 tap 段长度 |
| `0xD9` | W | 写任意值 = 按一下 `I_debug_button` 再松开 ⇒ **tap + 1** |
| `0xDA` | R/W | Bayer 相位：`0`=RGGB(默认) `1`=GRBG `2`=GBRG `3`=BGGR |

判读方法：

- `0xD7[6]=1` → 已锁定手动 tap（0x450D 起的正常状态）
- `0xD8[5:0]` 很小（<8）→ 这次扫描不可信；`≈32` 说明眼图接近满量程
- `0xD6[5]`=`in_frame`，`0xD6[6]`=`payload_valid` → 判断数据是否真的在走

配套脚本：

- `tools/board_csi_tap_sweep.sh` —— 逐 tap 步进并逐档抓图
- `tools/board_bayer_try.sh` —— 4 种 Bayer 顺序各抓一张

## 5. 仿真验证

`fpga/sim/tb_csi_full.v`：从**串行比特流**开始跑完整链路（不含 IDDR/LCLK，加密原语不能仿真），
覆盖 `byte_align → word_align → gear_box → packet_handler → 10bit_unpack → vid2stream`。

```
byte_align valid per lane          = 26/26/26/26
payload_valid pulses               = 10
unpack_valid  pulses               = 8
AXIS tvalid beats                  = 8
AXIS tuser pulses                  = 1
AXIS tlast pulses                  = 2
PASS: 串行输入 -> 出图通路 全链打通
```

中间字与源数据逐字节核对：包头 `0x3100102b`（ECC/WC/DT 全对），载荷 `0x11223344..47`。

写 TB 时踩过的坑（详见 `/memories/repo/mipi_lpfree_rx_sim.md`）：解串模型不能"凑"相位、
复位期间不能发比特、首帧 FS 必被吃掉（要发两帧）、预滚填充不能用 `0x00`（那是合法 FS 包头）。
