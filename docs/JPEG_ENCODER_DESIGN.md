# FPGA 硬件 JPEG 编码器设计方案

> 赛题指标：① JPEG 压缩在 **FPGA 硬件并行**实现 ② 通过 **MIPI x4** 输出至 RK
> ③ 支持**动态码率** ④ 支持**无损/有损双模式**

---

## 0. 前置结论：控制通路

赛题 ③④ 需要 RK → FPGA 下发参数。本板可用通路的实测结论：

| 路径 | 可用性 | 依据 |
|------|--------|------|
| I2C | ❌ 不存在 | 手册 §36/§37 只列 MIPI 4LANE + PCIe x1；`fpga_pin.adc` 中 FPGA 唯一来自 RK 的信号是 `I_dsi_en`；`milianke_mipi.c` 无任何 `i2c_transfer`/`i2c_smbus` 调用（`fpga@1a` 是 V4L2 虚拟占位节点）；`i2cdetect -y 9` 无应答 |
| PCIe x1 | ❌ 硬件不可用 | 用户确认 |
| **`I_dsi_en` (FPGA L13)** | ✅ **唯一可用** | 驱动 `s_stream()` 用 `gpiod_set_value_cansleep()` 驱动，软件可任意翻转 |

**CSI-2 是单向的**（FPGA→RK），无回传通道。因此：

- **控制**：`I_dsi_en` 复用为**单线串行命令通道**（UART 式帧格式，低电平持续 >5ms 才判为"关流"）
- **兜底**：FPGA 内部**自主逐帧码率控制**，即使命令线未接也能满足"动态码率"

## 1. 总体数据流

```
 IMX415 ──MIPI RX──> 解包 ──> 裁剪 ──> ISP ──> RGB888
                                                 │
                              ┌──────────────────┴──────────────────┐
                              │        JPEG 编码器（本方案）          │
                              │                                     │
                              │  RGB→YCbCr ──┬─> 有损: DCT+量化+熵编码 │
                              │              └─> 无损: DPCM + 熵编码   │
                              │                       ↑             │
                              │          ┌────────────┴──────────┐  │
                              │          │ 码率控制(逐帧调 Q)     │  │
                              │          │ 寄存器堆(Q表/模式/目标) │  │
                              │          └────────────┬──────────┘  │

                                          D-PHY TX 4 lane ──> RK3576 CSI3
                                                      │
                              RK: rkcif → 提取 JPEG → MPP 硬解(jpegd) → HDMI
```

## 3. 有损模式（SOF0 baseline）

### 3.1 吞吐预算（关键）

| 项 | 数值 |
|---|---|
| 输入像素率 | 1920×1080×60 = **124.4 Mpixel/s** |
| 工作时钟 | 148.5 MHz（`ui_dbuf` 读侧 `S_pclkx1`） |
| 单像素/时钟裕量 | 148.5/124.4 = **1.19×** |
| MCU 尺寸 | 16×8（4:2:2） = 128 像素 = 2 Y + 1 Cb + 1 Cr 块 |
| MCU 数 | 120×135 = 16200 /帧 → 972 k MCU/s |
| 每 MCU 可用时钟 | 148.5 MHz / 972 k = **152.8 clk** |
| 每块可用时钟 | 152.8/4 = **38 clk** |

**采样策略**：像素以 1 px/clk 连续流入行缓冲（占 84% 时钟），DCT 流水线从行缓冲取块，
两者用不同 always 块并行。DCT 采用**全并行 1 维**（8 个输出/时钟），单块约 24~30 拍，
留有 25% 余量。

### 3.2 DCT

采用 **AAN（Arai-Agui-Nakajima）** 算法：

- 1 维 8 点只需 **5 个乘法**（其余为加减/移位）
- 两次应用（行 + 列），中间经 **8×8 转置 RAM**
- 乘法器：`c(1)=0.980785`、`c(2)=0.923880`、`c(3)=0.831470`、`c(5)=0.555570`、`c(6)=0.382683`、`c(7)=0.195090`（Q15 定点）
- AAN 的缩放因子 **折进量化表**，不额外消耗乘法器

### 3.3 量化

- 8 个乘法器，用 **倒数定点乘法** 代替除法：`q = (coef * inv_q[j]) >>> 16`
- `inv_q` 由量化表基值 × 全局缩放算出，**每帧开头更新一次**（不是每块）
- 量化表基值来自寄存器堆（可运行时改）

### 3.4 熵编码

- DC：与上一块 DC 差分 → 幅度分类 SSSS → 霍夫曼(DC 表) + 附加位
- AC：ZRL(0xF0)/EOB(0x00) 游程 → 霍夫曼(AC 表) + 附加位
- **位打包**：32 位累加器 + 桶形移位；遇到 `0xFF` 输出后**补 `0x00`**（字节填充）
- 重启间隔（RSTn）可选

## 4. 无损模式（SOF3）

无损 JPEG（ITU-T T.81 Annex H）比 DCT 简单得多：

```
预测器：Px = f(邻近像素)          预测器选择 1~7
残差  ：Diff = Px - 实际值
编码  ：Diff 幅度分类 SSSS → 霍夫曼(无损 DC 表，Annex K 表 K.3)
```

- 复用同一套**位打包 / 0xFF 填充 / 标记生成**逻辑
- 预测器（用 MED/LOCO-I 效果最好）：
  ```
  a = 左, b = 上, c = 左上
  if (c >= max(a,b)) Px = min(a,b)
  else if (c <= min(a,b)) Px = max(a,b)
  else Px = a + b - c
  ```
- 与有损模式共用：YCbCr 转换、行缓冲、熵编码器、头部生成
- **切换点**：DCT/量化 与 DPCM 预测器 二选一，用寄存器 `MODE[0]` 选择

## 5. 动态码率

### 5.1 目标码率模式（CBR-like）

```
目标每帧字节数 = TARGET_KBPS * 1000 / 8 / 帧率
每帧结束时：
    err = 目标字节数 - 实际字节数
    accum += err                        // 积分项
    scale += (err * RC_SPEED + accum) >> SHIFT
    scale 限幅到 [MIN_SCALE, MAX_SCALE]
下一帧用新的 scale 重算 inv_q[]
```

### 5.2 质量模式（VBR）

直接按 `QUALITY` 寄存器映射到固定的量化缩放，不做闭环 —— 输出码率随内容自然变化
（这本身也是"动态码率"）。

### 5.3 双缓冲

`inv_q[]` 用**双缓冲**（乒乓），保证切换发生在帧边界，不会让帧内量化表变化。

## 6. 寄存器映射

| 地址 | 名称 | R/W | 说明 |
|------|------|-----|------|
| 0x00 | MODE | R/W | [0] 1=无损 0=有损；[1] bypass；[2] 只编码单帧 |
| 0x01 | QUALITY | R/W | 有损质量 1~100 |
| 0x02-0x03 | TARGET_BYTES | R/W | 目标每帧字节数，0=不限 |
| 0x04 | RC_ENABLE | R/W | 码率控制使能 |
| 0x05 | RC_SPEED | R/W | 收敛速度（默认 8） |
| 0x06 | SUBSAMPLE | R/W | 0=4:4:4 1=4:2:2 2=4:2:0 |
| 0x07 | RESTART_INT | R/W | 重启间隔(MCU)，0=不插 |
| 0x08 | PREDICTOR | R/W | 无损预测器 1~7，0=MED |

## 7. 传输：CSI-2 承载 JPEG

| 方案 | DT | 优点 | 风险 |
|------|-----|------|------|
| **A. 标准 JPEG DT** | 0x18 (JPEG 8-bit) | 符合规范 | **rkcif 是否支持待验证**（`/dev/video22` 目前只上报 YUV 格式） |
| **B. RAW8 承载** | 0x2E (RAW8) | rkcif 必然支持 | 需要把 JPEG 码流补足到固定帧长；RK 侧按字节流解析 |

**先做 A 的验证**（改 `milianke_mipi.c` 上报 `MEDIA_BUS_FMT_JPEG_1X8`，看节点是否出现 MJPG）；
不行则退到 B。两种情况下 FPGA 侧只是 `csi2_frame_tx` 的 DT 和长度策略不同。

### 变长帧问题

JPEG 帧长可变，而 CSI-2 按行/包发送。做法：

- 在码流前插入 **4 字节大端长度头**（或直接用 EOI 标记 `0xFFD9` 判帧尾）
- CSI-2 每包固定 4096 字节，最后一包短包
- 帧内不足一行的用 `0x00` 补齐（或让 `csi2_frame_tx` 支持变长）

### 8.0.1 已踩过的坑（都写进了代码注释）

| # | 现象 | 根因 |
|---|------|------|
| 1 | `No function named jpeg_q_lum` | `jpeg_defs.vh` 有 `ifndef` 保护，多文件编译时第二个模块整段被跳过。修：include 前 `undef` |
| 2 | DCT 输出 `got[k][t] == exp[k+1][t]` | 流水影子链少对齐一级（`s01` 是 2 拍延迟，`k3` 是 3 拍） |
| 3 | 小图 `y_mem[896] out of bounds` | 行缓冲组索引位宽写死 8 位；改为 `$clog2(GY)` |
| 4 | `W=192` 时输出 3 倍字节 | 地址用 `{buf,row,grp}` 位拼接，只有组数是 2 的幂时才等于 `buf*8*GY+row*GY+grp`。修：补齐到 `GYP = 1<<GYW` |
| 5 | 熵字节顺序 `d9 4b d6` 变成 `d9 bd 64` | 左对齐累加器方向写反：应 `acc \| (code << (64-n-len))`，不是 `(acc>>len) \| ...` |
| 6 | `n` 从 45 涨到 115，acc 溢出 | `n_p` 在空闲拍仍加残留在 `i_len` 上，而 `has_byte` 分支用 `n_p-8` 回写 `n`，导致 **n 不减反增** |
| 7 | 输出停在 640 字节，`acc=xX00...` | `i_ready` 未考虑 `n+i_len`，移位量下溢 → X 污染 → `pend_00=X` → 死锁 |
| 8 | 熵字节比参考少 1 字节，之后全错位 | `pend_00` 那拍把 `i_ready` 拉低，但 huff 上一拍已认为发出去了，**符号被静默丢弃** |
| 9 | 只差最后 1 字节 | `bp_flush` 后立即进 EOI，输出 mux 被 EOI 抢占，flush 的字节被挡掉 |
| 10 | `W>255` 时 SOF0 宽度错 | 宽度高字节硬编码成 0 |
| 11 | `1920x96` 每组字节数暴涨 10 倍 | tb 的 `mem` 写死 65536 项，`$readmemh` 越界读 X（RTL 无关，但会误导排查） |

**教训**：`reg` 数组的 `for` 复位在某些仿真器下不可靠，关键数组要另加 `initial` 初始化（`G/F/qzz/rz` 都加了）。
`always @(*)` 里用 `reg` 中间量会产生敏感表推断问题，改用 `generate + assign`。
