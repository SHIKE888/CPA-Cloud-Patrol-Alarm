# 逐级垂直错位：每过一级 3×3 窗口，画面下移 1 行

> 板子：VER 读 0x4704（实际已含 V47.7 的三项修复，版本号机制见 `FIX_2026-10-25_V47_7.md`）
> 场景：镜头静止，`tools/board_refcheck.py` 软件参考模型比对 + `fpga/sim/tb_shift2.v` 仿真

---

## 1. 板上实测（软件参考模型，12 帧平均）

`best_shift()` 在 ±12 px 内整数搜索，让"原图"与各模式输出对齐：

| 用例 | 水平 dx | **垂直 dy** | 对齐后 MSE | 与模型相关 |
|---|---|---|---|---|
| 原图 | 0 | 0 | — | — |
| 高斯 3×3 s8 | 0 | **−1** | 0.87 | 0.9985 |
| 高斯 5×5 s8 | 0 | **−2** | 1.21 | 0.9950 |
| 高斯 7×7 s8 | 0 | **−3** | 58.18 | 0.9779 |
| 高斯 3×3 s4 | 0 | 0 | 1.64 | 0.9995 |

- 水平已经修好（dx 全 0；旧 bit 上是 +4.7 / +8.2）
- 垂直 **严格 1 行/级**：1 级 → 1 行，2 级 → 2 行，3 级 → 3 行
- `s4`（50% 混合）刚好把"半行"量化掉 → 显示 0，反过来证明位移量就是 1 行/级

## 2. 仿真复现（`tb_shift2.v`）

图案：20 列 × 1 行的亮块（col 90..109, row 6, 值 200）。对称核模糊后垂直重心应仍在 row 6。

`preproc_basic` 每行亮度总和：

```
全关   f0 :  ...  row6=4000                      -> dy = 0   行
3x3    f1 :  ...  row6=1002 row7=2000 row8=1002  -> dy = +1  行
5x5    f2 :  row6=260 row7=1002 row8=1502 row9=1002 row10=260   -> dy = +2 行
7x7    f3 :  row6=60 row7=382 row8=940 row9=1260 row10=940 row11=382 -> dy = +2.9 行
```

- 3×3 的结果形状是**对称的** `[1002, 2000, 1002]`，只是整体比正确位置低 1 行 → **纯平移，不是滤波核错**
- 5×5 同样整体低 2 行
- 7×7 低 ~3 行，而且**最上面一行丢了**（只有 6 行有值，应为 7 行）—— 这就是 7×7 对不齐模型（MSE 58、相关 0.978）的原因

`preproc_top`（高级层，1 级窗口）：

```
mode 0 (原图)      dy = 0
Sobel/Prewitt/Laplace  dy = +1
中值               亮块被 3x3 中值完全滤掉（sum=0），该图案不适用
```

## 3. 根因

`preproc_win3x3_rgb` / `preproc_win3x3` 的行缓冲给的是：

```
mem2 = 第 Y-2 行        (wA)
mem1 = 第 Y-1 行        (wB)
直接输入 = 第 Y 行      (wC)
```

而 3×3 的卷积中心取的是 **`eB` = 第 Y−1 行**（`g_p1c` 里中心是 `b1`）。

于是：**在第 Y 个输出位置上，吐出的是"中心为第 Y−1 行"的滤波结果** → 整幅下移 1 行。
每级级联再加 1 行，所以 3 级高斯 = 3 行。

**因果性决定了这不是笔误能修的**：要输出"第 Y 行为中心"的 3×3 结果，必须已经拿到第 Y+1 行。
也就是说 3×3 天然要延迟 1 行；现在的实现延迟了 1 行取数据，却把结果摆在"没延迟"的位置上。

> 附带解释：这正是原作者说的「每行开头 16 像素是上一行行尾」的真正来源 ——
> 整幅下移 1 行在流式图像上看起来就是"行首那几组是上一行的内容"。
> `preproc_linefix` 只是把这个现象旋转掉了，没有消除根因。

## 4. 修法选项

| 方案 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **A（推荐）** | 在窗口模块输出端加一个**行缓冲**：结果先写入，下一行再读出。帧首第 1 行用第 0 行的结果顶替，行数守恒 | 每级 +1 行缓冲 ≈ 1920/4 × 96bit ≈ 46 kbit；3 级 ≈ 138 kbit（PH1A90 的 BRAM 足够） | 中：要重新对齐 `o_tvalid/o_tuser/o_tlast` 与行缓冲读写 |
| **B** | 保持现状，接受 1 行/级偏移，只用 rowmask 标记 | 零成本 | 画面在高斯/边缘模式下整体偏下 1~3 行；7×7 还会丢最上行 |
| **C** | 把窗口改成"中心 = 当前行"的 4 行缓冲（(Y-1,Y,Y+1) 需要 Y+1，仍要延迟一行），本质同 A | 同 A | 同 A |

方案 A 的具体落点：`preproc_win3x3_rgb.v` / `preproc_win3x3.v` 各加一组
「写指针一行 + 读指针落后一行」的 RAM，`o_win*/o_rgb` 从 RAM 读端出，
`o_tvalid/o_tuser/o_tlast` 相应再延 1 行（用 `lcnt` 计数一行 = W/4 拍）。
