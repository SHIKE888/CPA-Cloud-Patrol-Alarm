### 1.2 每行 16 像素错位（已定位、已修、已仿真验证）

**根因**：`preproc_win3x3_rgb` / `preproc_win3x3` 的 `o_winA/B/C` 用的是 `c_p2`（2 拍前）再寄存一级，
而 `o_rgb` 只延迟到 `rgb_d3` —— **像素比窗口早 1 拍**，每级固定错 4 像素。
basic 里 3 级 + edge 里 1 级 = **4 × 4 = 16 像素**，与板上实测完全吻合。

**修法**：像素/标志/rowmask 一并走 d4；行首组左邻钳位到本组。

**仿真**（`fpga/sim/tb_align*.v`，iverilog）全部 PASS：

| 场景 | 结果 |
|---|---|
| 32 列直通，逐像素列位置 | bad = 0 |
| 高斯 3×3 / 7×7（强度 8） | bad = 0，行首无跨行 |
| **4K 行长 3840（960 组/行）** | bad = 0，行缓冲不回绕 |
| 输入 6 行 → 输出行数 | 6 行，不丢不增 |

⚠️ **该修复需要重新综合烧写 0x4507 才生效**；板上 0x4506 + `0xFB=0` 时画面正常，故暂未烧。

## 2. 分辨率切换：已改为「重启切换」（V45.14）

### 2.0 最终方案与实测

**运行中切换不可靠，但"改配置 + 重启"完全可行**，已双向实测通过：

| 操作 | 结果 |
|---|---|
| 1080 → 4K（网页点击） | 板子重启 → **3840×2160 / 25.0 fps** |
| 4K → 1080（网页点击） | 板子重启 → **1920×1080 / 59.3 fps，CSI2 错误 0 条** |

实现：

1. 网页 `/api/mode` → 写 `/root/rk/deploy/mode.env`（`RES/W/H`）→ `systemctl reboot`
2. systemd unit 用 `EnvironmentFile=-/root/rk/deploy/mode.env`
3. 开机 `boot_start.sh` 按 `RES` 算尺寸、配 media、`exec` 推流
4. 前端等待 150 秒并自动重连，不需要刷新页面

代价：一次切换约 **70~90 秒**（整板重启）；换来的是 100% 不黑屏、不留脏状态。

### 2.1 为什么不能运行中切（历史证据）

**这块板上"运行时切换分辨率"无法做到稳定**，无论软件怎么调。4K 是 82.9% 链路占用，
切换时 sensor 重配置 + RK 侧 rkcif/D-PHY 重新初始化之间存在时序竞争，偶发失锁。
失败时 `dmesg` 是成片的 `MIPI_CSI2 ERR (ecc/crc)`，且**只能断电恢复**。

### 2.2 实测数据（同一版代码）

| 方向 | 结果 |
|---|---|
| 4K → 1080 | **12.1 s / 9.1 s** 成功；也出现过一次把链路打坏（ECC 从 4 千涨到 **16 万**条） |
| 1080 → 4K | 13.4 s / 18.1 s / 27.7 s 成功；**75 s 超时**失败多次 |

### 2.3 为什么 reboot 后第一次启动必定成功

- `dmesg` 证据：每次失败后 `s_stream(0)` 有、`s_stream(1)` 无（或调用了也锁不住）
- **运行期 `unbind/bind` D-PHY 行不通**（实测）：
  ```text
  unbind csi2-dphy3 → 成功（/dev/video22 消失）
  bind   csi2-dphy3 → EINVAL（probe 失败；该 D-PHY 的 hw 节点在设备树里不可单独绑定）
  ```
  一旦 bind 失败只能断电。
- **全工程搜不到 `xclr` / `sensor_rst` / `cam_rst`**：FPGA 没有控制 IMX415 复位引脚。

### 2.4 已经存在、不要重复造的软复位

FPGA 侧**每次切模式都会执行完整软复位**：

```verilog
// ui_imx415_reg.v 主表第 0~2 项
0:  {16'h3000, 8'h01}   // STANDBY = 1
1:  {16'h3001, 8'h00}   // REGHOLD = 0
2:  {16'h3002, 8'h01}   // XMSTA = 1（停 master）
// … 201 条配置全部重写（含 0x3020/21/22、0x3024/25、0x3028、0x3033、0x4004..0x4074）
// ui_cfg_imx415.v 表尾
0:  {16'h3000, 8'h00}   // STANDBY = 0
1:  {16'h3002, 8'h00}   // XMSTA = 0（master start）
```

外加 `RES_RST_CYCLES = 500 ms` 复位窗，`RES_RST_TX_SIDE = 1`（TX/VTC/ISP/预处理整条写侧都复位）。
**sensor 和 FPGA 发送侧都已经软复位，缺的是 RK 侧。**

### 2.5 本轮踩过的坑（教训，不要再走）

| 我加的改动 | 后果 | 现状 |
|---|---|---|
| SIGTERM handler 等采集线程 12 s 再退出 | 设备被多占 10 s，后续 `0xE0`/新进程全在竞争 → ECC 刷屏 | **已删除** |
| 启动前 `v4l2-ctl` 抓帧探测 + 重试 | 探测自身拉低/拉高 mipi-en，反而加剧 | **已删除** |
| 先停采集再杀进程（join 14 s） | 同样延长设备占用 | **已删除** |
| 进程内切换（不重启 web） | 外部 `release()` 打断阻塞的 `read()`，STREAMOFF 不完整 | **已删除** |
| 缩短 `start.sh` 的固定等待 | 4K 下 sensor 重锁不够 | **已恢复 V44** |

**当前 `_launch_start_script` 已完全回到最早能用的版本**：
`pkill -9` → `sleep 2` → 写 `0xE0` → `sleep 5` → `bash start.sh`。

### 2.6 建议

1. **平时固定 1080p**（当前即如此）
2. 需要 4K：**重启板子后直接以 4K 启动**（`/root/start.sh 4k`），不要在运行中切
3. 真要支持运行中切换，只能在硬件上引出一路 sensor 复位（XCLR/PWDN）到 FPGA，
   让 sensor 真正上电复位——这需要核原理图，且要改 RTL + 重新综合

## 3. 开机自启（已验证）

### 3.1 组成

| 文件 | 作用 |
|---|---|
| `rk/deploy/mipi-webstream.service` | systemd unit，`Type=simple`，`Restart=on-failure` |
| `rk/deploy/boot_start.sh` | 上电初始化：等设备节点 → 按需复位 FPGA → 配 media → `exec` 前台推流 |

设计要点：

- systemd 直接管 **python 进程**（`exec` 换 PID），不是 `start.sh` 的 `nohup` 后台进程
- `KillSignal=SIGKILL`：采集线程可能卡在 `select()`，只有强杀能确保退出
- `TimeoutStartSec=180`：含 FPGA 复位 + sensor 锁相 + AI 模型加载
- 日志走 `journalctl -u mipi-webstream`

### 3.2 ⚠ 关键坑：开机时不要写 0xE0

第一版 `boot_start.sh` 无条件写 `0xE0`，结果**每次开机都黑屏**：

```text
开机 → FPGA 刚加载 bit，0xE0 本来就是 0
     → 又写一次 0xE0 → res_chg 触发 500ms 复位窗 + sensor 重下整表
     → sensor 上电初始化时序被打乱
     → MIPI_CSI2 ECC 刷屏，fps=0
```

修法：读回 `0xE0`，**已是目标值就完全不碰**（与 `start.sh` 的 `set_mode` 一致）。

### 3.3 实测（断电/reboot 后自动启动）

```text
uptime: up 1 minute
unit:   active / enabled
结果:   1920x1080 fps=59.7
CSI2 错误: 0 条
```

### 3.4 运维方式

```bash
systemctl status  mipi-webstream
systemctl restart mipi-webstream      # 重启推流（约 10~15 秒恢复）
systemctl stop    mipi-webstream
journalctl -u mipi-webstream -n 50    # 看日志
```

改分辨率档：编辑 `/etc/systemd/system/mipi-webstream.service` 里的
`Environment=RES=0 W=1920 H=1080`（4K 用 `RES=2 W=3840 H=2160`），然后
`systemctl daemon-reload && systemctl restart mipi-webstream`。

⚠ 不要再手工跑 `/root/start.sh`，会和 systemd 抢同一个设备（unit 的 `ExecStartPre` 会清掉旧实例，
但手工启动的进程不受 systemd 管理）。
