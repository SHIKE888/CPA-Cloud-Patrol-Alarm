## 2. 窗口模块 4 像素错位 —— 恢复 HEAD 版（V45.16，commit `3769154`）

### 现象与证据

工作区里的 `preproc_win3x3_rgb.v` 曾被整体替换为“三行环形缓冲 + 独立读写指针”实现
（`git diff --stat`：147 增 / 130 删，`rgb_d4` 消失）。用 `tb_align2` 逐像素比对：

```
OUT row=1 start: 32 40 48 56 (expect 0 8 16 24)
bad pixels = 116        ← 4 行 x 32 像素 = 128，几乎全错
```

把 `o_rgb` 的取值源从 `b_d1` 改成 `b_d2` 后**结果一字未变**，说明错位在更前置的位置。

### 定位结论

用 `tb_win3x3` 打出内部状态，两点都错：

1. **写指针**：`i_tuser` 那一拍写入用的还是上电残留的 `wcol`，随后又 `wcol <= 0`，
   于是下一拍把同一地址覆盖 —— 每行第 0 组被第 1 组顶掉，整行数据整体往前挪一格。
2. **`o_rgb` 取错行**：`b_p128` 取的是 `b_*`（上一行，buffer B），而窗口中心 `cu` 在 `c_*`
   （当前行，buffer C）。实测 `rgb` 打印出的是上一行的值。

两处叠加正好是整 1 组 = 4 像素。

### 处理

不修补，直接**恢复 HEAD 版**（`preproc_win3x3_rgb.v` + `preproc_basic.v` 是配套的，延迟常数互相绑定）。
HEAD 版是仿真验证过的基线：两侧行缓冲 + 输入流直取当前行，不存在“读写同一地址”的竞争，
相位由 `i_tvalid/i_tuser` 延迟链自然对齐，并用 `lcnt_d3==0` 做行首钳位。

### 复测（全部 PASS）

```
tb_align  : total bad pixels = 0, out rows = 6
tb_align2 : bad pixels = 0, rows = 4        (每行 start 均为 0 8 16 24)
tb_align3 : bad = 0, frames = 1             (7x7 三级级联)
```

## 3. 直方图均衡重做 —— 去掉“防频闪”滑块（V45.16）

用户原话：**“直方图均衡不应该有防屏闪这个功能，本身就不应该屏闪”**。

### 先量化，再动手

新建 `fpga/sim/tb_he_flicker.v`：给**逐帧完全相同**的静止输入，输出就应当逐帧完全相同；
只要帧间有差，就是模块自己在制造频闪。

基线（`i_he_temp=0`，即默认配置）：

| 测试图样 | 帧间逐像素差异 | 最大帧间差 | LUT 校验和变化 |
|---|---|---|---|
| 结构图（渐变 + 固定噪声） | 1008/2048 | 1 | 0 |
| 平坦 + **每帧不同**噪声 (±16) | **2048/2048** | **222** | **0** |

关键发现：**LUT 完全不变，输出却整帧翻动，最大差 222**。
所以“频闪”不是 LUT 在跳，而是**陡峭的 LUT 把 ±1 的噪声放大成了几十级**
（CDF 的局部斜率 = 该 bin 的计数，计数小的 bin 一级能跳几十级）。

### 改法

删掉用户可调的 `0xFA BASIC_HE_TEMP`（双端 + 云端），改为内置两道闸：

1. **LUT 斜率硬限制** `LUT_SLOPE = 3`：每级输入最多升 3 级输出。
2. **帧间 IIR 1/4**：`new = (cur + 3*prev + 2) >> 2`。

> ⚠ **顺序必须是 IIR 在前、限斜率在后。**
> 第一次实现把限幅放在 IIR 之前，实测 `maxslope` 仍然是 8：
> 上一帧的陡坡会以 3/4 的权重透过 `lqp` 传回来，限幅形同虚设。
> 改成先 IIR 再 `clamp(t_raw, last, last+3)` 后，`maxslope` 才真正落到 3。

### 改造后实测

| 指标 | 基线 | 改造后 |
|---|---|---|
| LUT 最大斜率 | 8 ~ 9 | **3**（硬限） |
| 帧间最大差（±16 噪声） | 222 | **82** |
| 帧间最大差（静止图，收敛后） | 1 | **0** |
| LUT 逐帧 `maxdelta` | — | 1（收敛） |
| “防频闪”滑块 | 有（0xFA） | **已删除** |

`0xF9 BASIC_HE_CLIP`（对比限制）保留，仍可进一步压噪。

## 4. 单色算子红蓝偏色（V45.17，commit `36ca3a0`）

### 根因

`preproc_edge` 输出的每个像素是 `{8'h00, gv, gv, gv}`（R=G=B），
但下游 `preproc_post` 的数字白平衡对 R/B 各乘一个增益：

```verilog
g0 = {8'h00, gain8(p0[23:16], wb_r), p0[15:8], gain8(p0[7:0], wb_b)};
```

默认 `wb_r`/`wb_b` 只要不是 128，灰度图立刻被染成红/蓝。
这也解释了为什么只有 Sobel / 拉普拉斯 / Prewitt / 阈值 / 形态 / 中值 / 浮雕受影响，
而**原图和高斯不受影响**（它们三通道各有值）。

### 改法

`preproc_post` 增加 `i_mono` 端口，为 1 时整段跳过白平衡：

```verilog
wire [127:0] wb_rgb = i_mono ? i_rgb : {g3, g2, g1, g0};
```

`system_top` 接 `.i_mono (S_pp_mode != 4'd0)`。
`S_pp_mode` 已由 `cfg_ctrl_top` 同步到像素域，**没有新增跨时钟风险**。

### 仿真验证（`tb_mono_wb.v`，`preproc_top`(Sobel) 与 `preproc_post` **真实串联**）

固定 `wb_r=200`(1.56x) / `wb_b=50`(0.39x)：

| 配置 | `n_nonmono`（R≠G 或 G≠B 的像素数） | 与上游逐像素差异 | 示例 `in 24 →` |
|---|---|---|---|
| `i_mono=1` | **0 / 384** | **0** | `R24 G24 B24` |
| `i_mono=0`（对照组） | 320 / 384 | 320 | `R38 G24 B9` |

对照组证明“白平衡本身是好的、只是不该作用在单色图上”，修复点正确。

## 8. 仍需上板确认

以下都是**仿真结论**，未上板实测：

1. HE 在真实场景下的观感（斜率限 3 会不会让某些窄直方图场景“不够亮”）。
   若需要更强效果，把 `preproc_basic.v` 里的 `LUT_SLOPE` 调大（6/8），代价是噪点放大倍数同比上升。
2. 边缘算子的“噪点”：斜率限制解决的是 HE 引入的放大；边缘算子本身对噪声敏感是算法特性，
   如需进一步压噪，应在高级层之前加 3x3 预平滑（本轮未做，避免再动对齐链路）。
3. 4K 模式下的资源/时序（新增 `lut_last` 与几个 9 位比较器，规模很小，但仍应跑一次 TD 综合确认）。
