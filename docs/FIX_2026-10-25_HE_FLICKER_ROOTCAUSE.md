# HE 频闪的根因与修复（V47.8 / 0x4708）

日期：2026-10-25
优先级：用户指定「直方图闪烁是主要问题，其次是噪点」

---

## 0. 结论（一句话）

> **帧间 IIR 平滑（`new = (ideal + 3·prev)/4`）本身就是频闪的根源。**
> 它把 LUT 变成时间常数 4 帧的一阶低通，上电/切换/任何 ideal 变化后
> 要 10~20 帧才收敛；这段时间里**整帧亮度持续单调变化**，就是肉眼看到的"闪"。
> 删掉它之后 LUT **第一帧就锁定**，10 帧均值极差从 3536 降到 172（约 20 倍）。

---

## 1. 先排除的三个假设（都不是原因）

| 假设 | 验证方法 | 结果 |
|---|---|---|
| **AE 闭环**（HE 提亮 → AE 降曝光 → 再拉） | `tools/board_he_aeloop.py` 逐帧记录亮度 + CAM_EXP/CAM_GAIN | 曝光 SHR0 恒 1057、增益恒 60（20 帧**零变化**），亮度却 93.7→164.2、9 次符号翻转 → **排除** |
| **`hsel` 自由运行的相位** | `tb_he_flicker.v` 加 `+JIT=1`，行间插 1~5 拍随机空闲（像素内容完全不变） | JIT=0 → lutsum 30210；JIT=1 → 30046。有差异，但**同一抖动模式下完全稳定** → 不是振荡源 |
| **1/4 抽样 lane 的统计噪声** | 手算：总样本 ~129600，单桶 p=0.005 时 σ≈22，折算到 LUT 仅 ~0.04 级 | 撑不起 70 级摆动 → **排除** |

另外核对了一件容易混淆的事：板上读 `VER=0x4704` 不代表跑的是旧逻辑 ——
21:18 那份 bit 里残留 `.CFG_VER(16'h4704)` 覆盖，而修这个的提交（81fab2c）在 21:37，
之后没重编。**逻辑确实是 V47.7。**

## 2. 为什么原来的仿真台复现不了

`tb_he_flicker.v` 只有 512×32 = **2048 个像素**，直方图每桶只有个位数计数，
完全没有真实场景"大面积平坦背景 → 少数桶爆满 → 裁上限起作用"的特征，
所以它在仿真里始终稳定。

新建 `fpga/sim/tb_he_big.v`：
- **1920×1080、4 px/clk**（与板上完全一致），1080 行 × 480 组
- 峰形直方图：大片背景 84 + 中灰斜坡 + 高光块
- 每帧独立的逐像素噪声 ±2（模拟静止场景的真实噪声）
- **TB 侧自己统计一份直方图**，用它算「HE 之后的整帧均值」= Σ hist[b]·LUT[b] / N
  —— 就是板上实测从 93.7 摆到 164.2 的那个量
- 编译期开关 `-D SLOPE= -D IIR= -D VLINES=`，运行期 `+CLIP= +NF= +VACT=`

## 3. 决定性 A/B（静止场景、帧边界严格对齐）

`iverilog -D VLINES=48` + `+CLIP=8 +NF=6`，指标 = HE 后整帧均值（255 制）

| 配置 | 6 帧序列 | 帧间极差 | 行为 |
|---|---|---|---|
| 纯 HE（无斜率、无 IIR） | 28352 28350 28427 28417 28325 28402 | **102**（0.36%） | 第 1 帧即锁定 ✓ |
| 仅斜率限制 SLOPE=3 | 27453 27453 27541 27528 27467 27482 | **88** | 第 1 帧即锁定 ✓ |
| **仅 IIR** | 31600→30818→30251→29826→29485→29248 | **2352** | 单调漂移 ❌ |
| **斜率 + IIR（当时板上配置）** | 31600→30725→30022→29470→29023→28679 | **2921** | 单调漂移 ❌ |

IIR 那一行的 `lut[64]` 序列：

```
48 → 36 → 27 → 20 → 15 → 11
= 48 × 0.75^n     ← 教科书式一阶低通，τ = 4 帧
```

跑到 10 帧仍在漂：`31600 … 28064`，离真值 27453 还差 2.4 级。
**即上电后 15 帧左右画面一直在变亮/变暗。**

## 4. 修复

`fpga/uisrc/01_rtl/preproc/preproc_basic.v`

```verilog
// 原来
parameter [8:0] P_SLOPE = 9'd3;
parameter       P_IIR   = 1'b1;   // ← 元凶
// 现在
parameter [8:0] P_SLOPE = 9'd3;   // 保留：把噪声放大倍数硬限在 3 倍
parameter       P_IIR   = 1'b0;   // 关闭帧间 IIR
```

为什么「保留斜率限制、只删 IIR」是安全的：

1. **纯 HE 的帧间抖动只有 0.36%** —— 根本不需要时间平滑，原设计前提就是错的；
2. **噪点问题由斜率限制独立解决** —— 它把 LUT 局部斜率硬限在 3，
   噪声放大倍数 ≤3 倍（`tb_he_flicker` 实测 `maxslope=3`）；
3. 斜率限制是**逐 bin 组合**的，不跨帧，所以它不会引入滞后。

修复后同一实验（10 帧）：

```
27453 27453 27541 27528 27467 27482 27509 27575 27577 27625
```

- 帧 0 与帧 1 **完全相同** → 立即锁定
- 10 帧极差 **172**（= 0.67 级），全部来自逐帧噪声的统计抖动

## 5. 尚未解释的一点（必须上板确认）

板上实测是**双向**摆动（93.7 ↔ 164.2），而 IIR 只能解释**单向收敛**。
推测第二因素是：测试场景有 50 Hz 工频光源 → 每帧输入亮度本来就在小幅变化 →
IIR 以 3/4 的权重把上一帧的状态带过来，形成滞后跟踪。

**所以删掉 IIR 之后必须上板重测**：
- 若双向摆动消失、亮度稳定 → 根因确认，收工
- 若仍有双向摆动 → 说明还有第二个因素，下一步去查「统计窗口是否每帧盖到同一批像素」
  （`build_req` 靠数 `nw × v_active` 个 valid 拍判断帧边界，
  一旦 ISP 每帧拍数与 `nw*v_active` 有偏差，窗口就会逐帧滑动 —— 仿真台已留 `+VACT=`
  可直接做这个 A/B）

## 7. 复现命令

```powershell
cd fpga\sim
$s="$env:USERPROFILE\oss-cad-suite"
$env:PATH="$s\bin;$s\lib;"+$env:PATH; $env:YOSYSHQ_ROOT=$s

# 默认配置（P_SLOPE=3, P_IIR=0）
iverilog -g2005 -D VLINES=48 -o tb_fix.vvp tb_he_big.v `
  ..\uisrc\01_rtl\preproc\preproc_basic.v ..\uisrc\01_rtl\preproc\preproc_win3x3_rgb.v
vvp tb_fix.vvp "+CLIP=8" "+NF=10"

# A/B：强制打开 IIR，看漂移回来
iverilog -g2005 -D VLINES=48 -D "IIR=1'b1" -o tb_drift.vvp tb_he_big.v `
  ..\uisrc\01_rtl\preproc\preproc_basic.v ..\uisrc\01_rtl\preproc\preproc_win3x3_rgb.v
vvp tb_drift.vvp "+CLIP=8" "+NF=10"
```

> 跑之前先 `Get-Process vvp,iverilog` 清掉残留进程 —— 本机上曾有 3 个 10/21 就在跑的
> 僵尸 vvp 各烧了 15 万秒 CPU，把 CPU 打满，仿真会"久等不出结果"。
