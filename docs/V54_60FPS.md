# V54 (0x5400) —— 双路 1080p60 全链收敛

> 目标：`双 IMX415 采集 → 3840×1080 拼接 → 硬件预处理 → 4 引擎 JPEG → CSI-2 变长帧 → RK3576`
> 全部跑起来，帧率贴近 60fps。本文记录**每一条硬门限的算式**、仿真证据和回退办法。

---

## 1. 本版改了什么

| 项 | V53c (0x5303) | V54 (0x5400) |
|---|---|---|
| 像素/编码域时钟 `S_clk_70m` | 70.238 MHz（PLL C3 21 分频） | **73.75 MHz（C3 20 分频）** |
| JPEG 一帧耗时 | 17.45 ms → 57.3 fps | **16.62 ms → 60.19 fps** |
| sensor 帧率 | 60.0 fps（VMAX=2283） | 不变（60.0 fps） |
| 结果 | 编码慢于输入 ⇒ 持续溢出 | 编码快于输入 ⇒ 不溢出 |

V53c 已经解决的两件事（本版沿用，不再改）：

1. `jpeg_seg_merge4` 的 `i_start` 不再接"引擎0 `st_busy` 上升沿"，只接 `S_enc_rst_rel`
   —— 这是 4 引擎全链死锁的**真正根因**，详见 `system_top.v` 里 V53b 那段注释。
2. `jpeg_byte_bridge` `AW 9→12`（4KB）、`jpeg_enc_if` `AW 11→12` + `START_LEVEL 3840`（16 行预取）。

时钟（以代码为准，不用文档里的旧注释）：

| 时钟 | 频率 | 来源 |
|---|---|---|
| `S_pclkx1` | 147.5 MHz | PLL C1 = VCO1475/10 |
| `S_clk_70m` = `S_st_clk` = `S_enc_clk` = `S_hs_rx_clk` | **73.75 MHz** | PLL C3 = VCO1475/20 |

> VCO = 25 MHz × 59 = 1475 MHz；C1=1475/10、C2=1475/2（737.5M DDR）、C3=1475/20。

## 3. 60fps 的三段算术（缺一段都到不了 60）

### 3.1 前端吞吐（够）
拼接输出 3840 px/行 × 1080 行 × 60 fps = 248.8 Mpx/s。
4 px/clk ⇒ 需 ≥ **62.2 MHz**。73.75 MHz 提供 295 Mpx/s，余量 **18.6%**。

### 3.2 编码吞吐（瓶颈）
每引擎 960×1080 ⇒ 8100 MCU；实测 **151.3 clk/MCU**。

$$
T_{enc} = \frac{8100 \times 151.3}{73.75\text{MHz}} = 16.617\ \text{ms} \;\Rightarrow\; 60.19\ \text{fps}
$$

输入帧周期（IMX415 VMAX=2283 行 × 7.3 µs）= 16.66 ms ⇒ 60.0 fps。
**16.617 < 16.66，余量 0.26%** —— 这就是必须提频到 73.75MHz 的原因：
70.238MHz 下是 17.45 ms（57.3 fps），**每帧欠 4.5%，会一直溢出**。

### 3.3 传输（够）
一帧 JPEG 约 120~200 KB，变长帧直接发，@125MHz×4B = 500 MB/s 容量；
60fps 只需 12 MB/s。定长帧（补零到 8.29 MB）要 497 MB/s，**物理上不可能**，
所以必须 `0x0B[2]=0`（不补零）+ 内核放行 `CSI_SIZE_ERR`。

## 4. 时序风险与回退

73.75 MHz 的 clk3 域实测 fmax ≈ **73.9 MHz**（V51 布线后 SWNS +0.793ns @14.237ns，
数据路径 13.444ns ⇒ 74.4MHz），余量只有 **0.2%**。

**综合后必看**：`phy_1/final_timing.rpt` 里 `S_clk_70m` 那一行的 Setup WNS。

- **WNS ≥ 0** ⇒ 直接用，60.19fps 达成。
- **WNS < 0** ⇒ 走"稳 57fps"回退，两处同时改（缺一不可）：
  1. `fpga/uisrc/03_ip/al_ip/ui_pll/ui_pll.v`：
     `CLKC3_DIV 20→21`、`CLKC3_CPHASE 19→20`、`CLKC3_DUTY_INT 10→11`
  2. `fpga/uisrc/03_ip/ui_imx415_cfg/ui_imx415_reg.v` 的 binning 分支 VMAX：
     `0x3024: 0xEB→0x60`、`0x3025: 0x08→0x09`（2283→2400 行；2400×7.3µs=17.52ms ⇒ 57.08fps），
     且 `system_top.v` 的 `.i_vmax(... 20'd2283)` 同步改 2400（只影响曝光换算）

  ⚠ 只改 PLL 不改 VMAX ⇒ sensor 仍发 60fps，继续溢出；
  ⚠ 只改 VMAX 不改 PLL ⇒ 57.1fps 输入配 57.3fps 编码，可行但地板上钉死 57fps。

## 6. 上板验收顺序（每步都别跳）

1. **只烧 SRAM/volatile**（绝不勾 flash），断电即回落 flash 里的兜底版。
2. 读 `0xA9/0xAA` 确认 `CFG_VER == 0x5400`（`0xA9`=0x00, `0xAA`=0x54）。
3. `0x0B = 0x01`（变长帧，DT=0x1e）。
4. 看 `0xA7`（桥写停顿）、`0xE4/0xE5`（桥水位/读计数）是否在动。
5. 看 `0xA0~0xA2`（**上一帧字节数**）—— 由 0 变非 0 才说明真的出过帧。
6. RK 侧 `/dev/video22` 抓一帧，首两字节必须是 `FF D8`，尾两字节 `FF D9`。
7. 网页 9012 直通 JPEG，确认不是黑屏/绿屏。

> ⚠ 反复 `systemctl restart` 会把 FPGA↔RK 的 CSI-2 弄失锁（dmesg 刷 ECC/CRC），
> 一旦看到就直接整板 reboot，别在寄存器层挣扎。
