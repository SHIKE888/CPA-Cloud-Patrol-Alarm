> 被侧模块：`fpga/uisrc/01_rtl/preproc/preproc_basic.v` + `preproc_win3x3_rgb.v`

## 0. 复现方法

```powershell
$s="$env:USERPROFILE\oss-cad-suite"; $env:PATH="$s\bin;$s\lib;"+$env:PATH; $env:YOSYSHQ_ROOT=$s
cd fpga\sim
iverilog -g2005 -P tb_he_flicker.PAT=1 -P tb_he_flicker.EN=2 -P tb_he_flicker.G_KER=0 `
    -o gk.vvp tb_he_flicker.v ..\uisrc\01_rtl\preproc\preproc_basic.v ..\uisrc\01_rtl\preproc\preproc_win3x3_rgb.v
vvp gk.vvp
```

- `tb_he_flicker.v`：多帧静止输入，统计帧间逐像素差、LUT 快照差
  - `PAT=0` 窄梯度+固定噪声 / `PAT=1` 单像素脉冲 / `PAT=2` 平坦固定噪声 / `PAT=3` 平坦+**每帧不同**噪声
  - `EN` 位图（2=高斯，4=HE，0=全关直通）
- `tb_win3x3.v`：单独验证窗口生成器，像素值 = `行*100+列`，一眼看行列

## 1. 结论一：全关（`EN=0`）输出与输入**逐像素一致**

```
DIFF frame 2 vs 3 : ndiff=0 maxdiff=0
f2 row16 = 140 148 148 156 ...      ← 与 IN row16 完全相同
```
说明延迟链（`rgb_d8` / `v_d8`）本身没问题，问题只在"窗口链"与"像素链"的相对对齐。

---

## 2. 结论二：高斯滤波输出整体偏移 **(Δx = -4 像素, Δy = +1 行)**

输入：全 128，仅 `(x=20, y=16)` 一个像素 = 255。只开高斯（`EN=2`），`str=8`。

| 核 | 输出峰值位置 | 应出现位置 | 偏移 |
|---|---|---|---|
| `KER=0` (3x3) | (16, 17) | (20, 16) | (-4, +1) |
| `KER=1` (5x5) | (16, 17) | (20, 16) | (-4, +1) |
| `KER=2` (7x7) | (16, 17) | (20, 16) | (-4, +1) |

三种核偏移完全相同，说明不是级联累积，而是**每一级的同一个对齐错误**：

```
KER=0 实测：
  row15: 全 128
  row16:       136 144 136   (col 15,16,17)
  row17:       144 160 144   (col 15,16,17)   ← 卷积中心跑到了 row17
```

### 根因（`preproc_win3x3_rgb.v`）

**(a) 垂直 +1 行**：窗口提供的是 `A=上上行, B=上一行, C=当前行`，
而 3x3 二项式的中心权重 4 落在 **`b1`（B 行）**：

```verilog
wire [11:0] gsum = a0 + 2*a1 + a2
                 + 2*b0 + 4*b1 + 2*b2   // ← 中心是 eB = 上一行
                 + c0 + 2*c1 + c2;
```
也就是说滤波结果属于**第 n-1 行**，但 `o_rgb <= rgb_d4` 贴的是**第 n 行**的像素
→ 整幅图下移 1 行。

**(b) 水平 -4 像素**：`o_win*` 是 **4 拍**延迟（`cur_d2 → c_p1 → o_win`），
而 `o_rgb` / `o_tvalid` 是 **5 拍**延迟（`rgb_d1..d4 → o_rgb`）。
窗口比像素新 1 拍 = 1 组 = 4 像素。

`tb_win3x3.v` 单测（`值 = 行*100+列`）直接看到：

```
OUT#0  rgb= 0  1  2  3 | C: 7 4 5 6 7 8     ← 中心是 4..7，比 rgb 超前 1 组
OUT#4  rgb=100..103    | C: 103 104 105 106 107 108
```

**(c) 级联对齐**：`preproc_basic.v` 里三遍结果的延迟分别是
`p1_d8=13 拍, p2_d4=14 拍, p3_pack=15 拍`，而原图 `rgb_d8=13 拍`。
选 5x5 / 7x7 时滤波结果比像素晚 1~2 拍（又被 (b) 的超前部分抵消，所以看起来都是 -4）。

---

## 3. 结论三：直方图均衡的 LUT **比像素晚 1 拍（4 像素）**

只开 HE（`EN=4`，`str=255`），输入窄梯度 `96..159`。

实测输出满足 `OUT[x] = LUT(IN[x-4])`：

```
IN  row16 = 140 148 148 156 156 156 100 100 100 108 ...
OUT row16 = 139 139 139 171 187 219 219 248 248 248  26  26  26  58  58  90 ...
LUT 反推:  LUT(140)=187  LUT(148)=219  LUT(156)=248  LUT(100)=26  LUT(108)=58  LUT(116)=90
```

逐项吻合 → **整幅画面右移 4 像素，每行开头 4 像素取的是上一行末尾的值。**

根因：`lq*` 比 `cl*` 多一级寄存器（`lq0 <= lut0[c_l0]` 在 `c_l` 之后又打一拍），
而 `lq_d8` 与 `cl_d8` 都只延迟 8 级：
```
cl_d8 = w_rgb(5) + 8 = 13 拍
lq_d8 = w_rgb(5) + LUT读(1) + 8 = 14 拍   ← 多 1 拍
```
于是 `hd = hv - cl` 是"邻居像素的 LUT 值 - 当前像素"。

---

## 4. 结论四：静止输入下 HE **不会自激频闪**

`PAT=3`（平坦 128 + 每帧不同的伪噪声，W=256/L=64），`EN=4`，`temp=0`：

```
frame 0..5 : lutsum = 32637 (每帧完全相同)
LUT DIFF frame 1 vs 2 : nbins=0 maxdelta=0
LUT DIFF frame 2 vs 3 : nbins=0 maxdelta=0
...
```

**统计路径本身是稳的：直方图 → CDF → LUT 这条链没有逐帧抖动。**

但有两个会"放大成可见闪烁"的现实因素：

1. **LUT 查表错位 4 像素**（第 3 节）：`hd = hv - cl` 在边缘处永远配错邻居，
   LUT 只要有 ±1 变化，输出就跟着跳——这是"防频闪"要掩盖的东西，但它是 bug，不是特性。
2. **HE 把窄分布暴力拉伸**：上例输入 111..143（33 级），输出被打到 0..255，
   放大约 **8 倍**。传感器噪声 ±16 → 输出 ±128，视觉上就是噪点狂闪。

另外：复位后 `S_INIT`（256 拍）期间统计被丢掉，首帧直方图不完整
（`fsm_in_valid=250`），第 1→2 帧 LUT 有 ±1 差异，第 3 帧起稳定。
这只是一次性上电瞬态，不是持续频闪。

## 5. 修复建议（按优先级）

| # | 位置 | 改法 | 解决 |
|---|---|---|---|
| 1 | `preproc_win3x3_rgb.v` | `o_rgb` 改为取 **B 行同组像素**（`b_p1` 拼成 128 位）而不是 `rgb_d4`；同时窗口输出再打一拍（`o_win*` 4→5 拍），使窗口/像素都在 5 拍 | 行列同时归零 |
| 2 | `preproc_basic.v` | 三遍结果与像素统一到 **15 拍**对齐（`rgb_d10` / `p1_d10` / `p2_d5`），不要再混用 13/14/15 | 5x5、7x7 不再偷偷偏移 |
| 3 | `preproc_basic.v` | `lq` 与 `cl` 同延迟（`lq_d7` 或 `cl_d9`） | HE 不再右移 4 像素 |
| 4 | `preproc_basic.v` | `S_INIT` 完成后丢弃第一个不完整帧的统计（等一次 `build_req` 后才允许 `S_IDLE` 累加） | 上电首帧不抖 |
| 5 | — | 修完 1~3 后再评估 `i_he_temp` 是否还需要；**建议默认改 0**（用户观点：正常不该需要它） | 去掉"防频闪"依赖 |

> 注意：修 1 会让 `preproc_basic` 的输出相对输入滞后 1 行（3x3 必须看到下一行才能算中间行），
> 行数不变、帧结构不变，只是相位下移 1 行；`preproc_linefix` 的"行首 16 像素"补偿需一并复核。
